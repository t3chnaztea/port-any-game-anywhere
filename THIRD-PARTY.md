# Third-party material and tools

Original project code and documentation use the [MIT license](LICENSE). Original example assets use CC0 only where explicitly marked. Third-party material retains its own license. Research links do not grant permission to copy a project’s source, branding, screenshots, or game data.

## Referenced projects

The research and documentation discuss external repositories as primary sources. They are not bundled dependencies unless a specific example says otherwise. See [the research record](docs/research.md) for source links and access dates.

The Sonic CD Saturn case study summarizes internal source and documentation review. It distributes no SEGA game data, BIOS, disc image, soundtrack, or built game. Its internal reports have not yet received a public evidence export.

The Fifteen pilot concerns the Fifteen game in [Simon Tatham’s Portable Puzzle Collection](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/). Its existing web port must be disclosed. Pin an upstream revision and preserve the applicable upstream license and notices when material is included in the pilot. Do not extend a license statement about source code to unrelated assets or platform dependencies.

Switchboard is the project’s original controlled recovery fixture. Its example-specific notices identify which files are original code and which assets are CC0. The original source remains evaluator-held during a blinded trial. That temporary access restriction is an evaluation control, not a permanent proprietary dependency.

## Optional tools

Codex, Claude Code, Ghidra, Java, compilers, debuggers, Emscripten, emulators, Node, Python, browsers, and device firmware have their own terms and licenses. The skill does not bundle them or automatically install them. Naming a tool is not an endorsement or a compatibility guarantee.

Ghidra is a program-analysis tool used in the planned Linux x86-64 recovery route. A decompiler attempts to turn machine instructions into higher-level source. Its output may need substantial interpretation and correction. It does not establish the right to redistribute the original program or the recovered output.

## Asset policy

Do not add proprietary game data to the repository, test fixtures, issue attachments, or release archives. Prefer original fixtures for public demonstrations. Where user-supplied assets are required, record their required identity without publishing their contents.

Before adding a third-party file, record its source URL, revision, license, attribution, and redistribution requirements. Check the exact files being added. Keep those notices beside the affected material. A generated screenshot, trace, or extracted data file may still contain restricted material.
