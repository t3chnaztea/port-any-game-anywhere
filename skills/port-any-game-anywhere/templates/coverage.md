# Coverage report

This report summarizes the authoritative completion ledger. It is not another ledger.
Record the inventory revision/date, ledger identity, profile, target, and report date.

## Defined population

Describe how known modes, routes, mechanics, transitions, saves, failures, and
endings were found. Name the finite required-claim set before calculating a ratio.
State unknown regions and exclusions. New discoveries require a revised inventory.

## Counts

Copy current counts from the checked ledger. Report satisfied required claims over
all known required claims for each profile/target. Keep failed, blocked, interrupted,
skipped, and untested claims in the denominator. Optional claims stay separate.
Zero required claims does not establish completion.

| Evidence class | Required claims | Current satisfying evidence | Open claims |

| Source inspection | Count from ledger | Current records only | Link IDs |
| Controlled fixtures | Count from ledger | Current records only | Link IDs |

## Interpretation

State exactly what this known set covers. Do not imply every possible input was
tested. Do not add these overlapping class counts into a global percentage.
Source inspection, fixtures, gameplay, emulators, and devices prove different things.
Record stale or malformed evidence and changed denominators, not only passes.
